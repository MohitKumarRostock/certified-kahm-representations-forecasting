KAHM soft-state forecasting: from representation to a checked risk bound

Guided demonstration · version 0.1.0

This notebook connects one observed history to its geometry-induced features, three fitted forecasts, and the archived evidence supporting their fitted-risk bounds. It uses the completed four-state benchmark supplied with this package.

You will learn to:

  1. Identify exactly what has been inspected or recomputed.
  2. Read RAW, KAHM MEM, and KAHM LOCAL representations for the same history.
  3. Distinguish calibration error q, a statistical upper bound U, and the benchmark's exact population risk R.
  4. Launch a separate fresh experiment and understand what must change for new data.

Default: archive inspection. Saved outputs below are an executed inspection example. They do not certify the runtime in which you open this file. Run the cells in order; change MODE to "verify" only when you intend full numerical verification. The mode is repeated in each results section.

2. Establish the scope before reading a result

inspect_primary checks the three fixed release anchors and their bound payload inventories. It reads the recorded results without evaluating a model, checking a confidence-endpoint inequality, or recomputing a population expectation. This is useful for learning and for checking that the archive is intact.

verify_primary invokes the strict existing verification chain and then replays the three selected-history predictions. It does not refit models, sample new calibration observations, or search for new endpoints.

Verification stops on an incompatible runtime or changed evidence. It never substitutes archive inspection for a failed numerical check. Python and NumPy version pins alone are insufficient: the stored identity also includes the full Python build string and NumPy/BLAS build configuration. A mismatch calls for an explicit fresh run in your environment, with its own freeze and assessment.

# Clear a previous result before attempting a new mode in this kernel.
result = None
if MODE == "inspect":
    result = inspect_primary(PROJECT, history=history_labels)

3. One benchmark, three matched representations

The observation alphabet is 0, 0.25, 0.75, 1, indexed by four state labels. The history contains two observations in time order. There are 16 possible histories and 64 history-target combinations. The package supplies independent episodes under a stipulated stationary history and transition law; it does not treat overlapping windows from a single trajectory as independent calibration. Each episode draws an ordered state pair (a, b) uniformly. Its next state is (a + b) mod 4 with probability 17/20, and each other state with probability 1/20.

The public primary development run used 4,096 training episodes and 1,024 validation episodes. It retained all 225 declared readout candidates, then froze the selected RAW, MEM, and LOCAL predictors before accessing the 4,096 calibration outcomes. MEM and LOCAL use the same validation-selected bank. The selected bank and actual widths appear in the recorded result below.

Representation Input to the readout feature/scaling stage Width
RAW Two observations after stored training-only standardization 2
KAHM MEM Concatenated soft memberships for two partitions 6
KAHM LOCAL The same six memberships plus membership-weighted local PCA coordinates of the input Determined by the selected bank

Each partition's memberships normalize separately. The concatenation is not one six-way probability distribution. These are geometry-induced features; the demonstration does not identify them as latent-state posterior probabilities. For standardized history z, each LOCAL block is phi_j * P_j.T @ (z - mu_j): membership times the input's centered local coordinates, not the reconstruction.

5. Keep q, U, and R separate

For a fixed fitted predictor, the loss is squared error between the clipped scalar forecast and the target, both in [0, 1]. The loss is therefore in [0, 1].

Quantity Meaning Evidence used
q The average calibration loss for this fitted predictor The reserved 4,096 episodes
U A verified statistical upper bound on its population MSE, under the declared premises The fixed allocation, bounded-loss method, and exact/direct numerical checks
R Its exact population MSE under this known benchmark law All 64 weighted history-target cases, evaluated after certification

The fixed family allocation is 1/60 per predictor, totaling 1/20. Conditional on development and under the stipulated iid calibration model, independent of development, the three upper bounds have at least 95% simultaneous coverage. Sharing calibration observations does not require independence between the three bounds. PRNG stream labels alone do not establish the iid premise. More precisely, the conditional probability that any reported valid U misses its fitted risk is at most 1/20. There is no additional conditioning on numerical availability or acceptance, and an unavailable candidate's allocation is not reassigned.

The requirement is population MSE at most 1/10. The certificate reports requirement_met when its verified exact U is at most 1/10. It is a risk bound for the complete fitted computational predictor, not a prediction interval for the next observation or a certificate of representation optimality.

In the following table q and R are rounded displays. U is displayed upward; saved exact fractions govern comparisons. In inspect mode all three quantities and the status columns are read from the hash-bound archive.

6. Interpret the result without discarding difficult cases

Certificate status Meaning
requirement_met The verified exact U satisfies U ≤ 1/10 under the stated premises
unresolved A valid U exceeds 1/10; this does not establish that the actual risk exceeds 1/10
certificate_unavailable No endpoint was established under the fixed numerical procedure

The separate audit reports covered, coverage_miss, or endpoint_unavailable. All candidates and all outcomes are retained. A coverage miss is an observed failure of a bound to cover this benchmark risk; it must not trigger selective rerunning until a favorable result appears.

The table retains the actual status of every public primary candidate. This is one realized audit. It does not estimate long-run coverage frequency or demonstrate that a representation is generally superior. The benchmark's Bayes risk is 9/160 = 0.05625; a realized sample mean q can lie below that population reference without a contradiction.

To understand the mathematical and implementation layers, read the certificate design and the population audit. The fitted-risk guarantee supplies the self-contained proof. The package assesses the particular implemented frozen predictors under its stated evaluation assumptions.

7. Run one fresh experiment explicitly

Use a new directory. The command below performs the complete established workflow in your runtime. It commits a reproduction plan before work, retains all 225 development fits, freezes the selected three predictors, materializes the reserved calibration stream, issues the assessment, and audits the result.

python -m kahm_demo reproduce --output runs/tutorial --master-seed 20261110 --run-id tutorial-v0.1

This command is displayed here; the notebook does not execute it. The output contains data/, encoders/, models/, frozen/, certificates/, audits/, and reproduction.json. Pipeline completion is distinct from certificate acceptance or realized coverage. Partial failures and unfavorable results remain recorded; there is no automatic resume, overwrite, resampling, or retry.

After a successful pipeline completion, verify that new run with:

python -m kahm_demo verify-audit --audit runs/tutorial/audits/audit.json --certificate runs/tutorial/certificates/certificate.json --bundle runs/tutorial/data --freeze runs/tutorial/frozen/freeze.json

The tutorial helper intentionally remains anchored to the original primary evidence. It does not select a newly favorable run. Reusing a seed/run identity is reproducibility, not new independent evidence. The public primary run ID is public-v0.1.0.

8. Move toward a new application

This release is an executable controlled benchmark. It does not yet provide a general CSV adapter or a theorem that makes arbitrary time-series windows iid. The following decisions come before a new application-specific certificate:

Decision What must be made explicit
Forecast task History, target, horizon, loss, and population distribution
Data separation Training, validation, independent calibration, and leakage controls
Representation and decoder KAHM construction, candidate menu, scaling, clipping, and fitting rules
Certificate premises Loss range, calibration dependence assumptions, confidence allocation, and numerical method
Provenance New source identities, runtime, model freeze, protocol, and retained outcomes
Optional oracle Use an exact population audit only when the evaluation law permits it

A justified fitted-risk upper bound need not have an exact population oracle. For a general dataset, unknown R must remain unknown; it cannot be relabeled from a test-set mean. Overlapping dependent windows need an appropriate sampling or concentration argument, and changed targets or losses need newly justified bounds. Multi-step latent rollouts require their own modeling and certification.

Continue with the full tutorial and the adaptation guide, which map these decisions to the current modules. Validation evidence for this release is in the release validation report.
